# Bàn giao BravoForest RVM — 23/10/2026

## 1. Trạng thái mã nguồn

- Repository: `https://github.com/VanQuang070805/BravoForestRVM`
- Nhánh bàn giao: `semi-final`
- Ứng dụng khách hàng: `http://<IP-Windows>:3000`
- Ứng dụng quản trị: `http://<IP-Windows>:3001`
- Kiosk: `http://<IP-Pi>:3002` hoặc `http://127.0.0.1:3002` trên Pi
- API NestJS: `http://<IP-Windows>:4000/api/v1`
- Camera AI trên Pi: `http://127.0.0.1:8765`

Các tiến trình local đã được dừng trước khi bàn giao. Secret, mật khẩu, `.env`, API key máy và dữ liệu runtime SQLite không nằm trong Git.

## 2. Cấu trúc hệ thống

1. Windows chạy MariaDB/XAMPP, Redis, API, worker, web khách hàng và web quản trị.
2. Raspberry Pi chạy kiosk bằng Docker và controller Python riêng.
3. Controller giữ frame mới nhất, chạy model NCNN khoảng 3 lần/giây, điều khiển Arduino qua USB Serial và chỉ gửi sự kiện cuối cùng tới API.
4. API ghi `deposit_items` theo idempotency key. Điểm chỉ được chốt trong giao dịch database khi phiên hoàn tất; vật AI nhận đúng nhưng cơ cấu chưa hoàn tất không được cộng điểm.
5. Customer, admin và kiosk cùng đọc một database qua API, không có dữ liệu giao dịch giả trong code giao diện.

## 3. Luồng nhận vật thể hiện tại

- `clean_pet` → PET; hiển thị ngay `PET sạch — đang xử lý` trên kiosk.
- `can` → lon nhôm; cần cảm biến kim loại xác nhận.
- `dirty_pet` và `bottle_cap` → AI từ chối, không cộng điểm.
- Khi cảm biến/cơ cấu lỗi, kiosk hiển thị `Lỗi thiết bị` thay vì gộp vào `Không hợp lệ`.
- Khi cơ cấu hoàn tất, controller đưa sự kiện vào SQLite cục bộ, gửi API với idempotency key, rồi kiosk đọc bản ghi thật từ database.
- AI không được tự cộng điểm nếu thiếu Arduino. Khi không tìm thấy Serial, launcher chuyển sang `CAMERA_ONLY`.

## 4. Dữ liệu và seed

- `database/BravoForest.sql`: schema đầy đủ.
- `database/seed_reference_data.sql`: danh mục tối thiểu, không tạo dữ liệu giả.
- `database/seed_machine_rvm01.sql`: máy thật `RVM-01` tại `12 Chùa Bộc`, hai rule AI và thùng PET/ALU; không chứa API key hay giao dịch.
- `database/migrations/`: migration tài khoản, đổi điểm thành tiền, chốt phiên ACID, timeout 5 phút và lỗi cảm biến.

Thứ tự khởi tạo máy mới:

```powershell
Get-Content -Raw -Encoding utf8 .\database\BravoForest.sql |
  D:\xampp\mysql\bin\mysql.exe -u root --default-character-set=utf8mb4
Get-Content -Raw -Encoding utf8 .\database\seed_reference_data.sql |
  D:\xampp\mysql\bin\mysql.exe -u root --default-character-set=utf8mb4 BravoForest
Get-Content -Raw -Encoding utf8 .\database\seed_machine_rvm01.sql |
  D:\xampp\mysql\bin\mysql.exe -u root --default-character-set=utf8mb4 BravoForest
```

Sau khi seed, lấy `machine_id`, `PET_RULE_ID`, `CAN_RULE_ID` từ hai kết quả cuối. Tạo API key mới trong admin hoặc bằng quy trình quản trị, chỉ lưu key thô vào `deploy/pi/.env`; database chỉ lưu bcrypt hash.

## 5. Cấu hình không được đưa lên Git

Tạo các file từ `.env.example`:

- `.env` ở root cho API/database/Redis/SMTP.
- `deploy/pi/.env` trên Pi cho `RVM_MACHINE_ID`, `RVM_API_KEY`, URL API, rule ID, camera và Serial.

Giá trị Pi cần kiểm tra:

```dotenv
MANAGEMENT_API_HOST=<hostname-mDNS-của-Windows>.local
MANAGEMENT_API_PORT=4000
MANAGEMENT_API_URL=http://<IP-Windows>:4000/api/v1

PET_RULE_ID=<rule-PET-AI>

ARDUINO_SERIAL_PORT=auto
ARDUINO_PROTOCOL=legacy
CAMERA_BACKEND=picamera2
CAMERA_WIDTH=640
CAMERA_HEIGHT=480
AI_IMAGE_SIZE=320
AI_INFERENCE_FPS=3
AI_STABLE_FRAMES=3

```

## 6. Khởi động và dừng

Windows, tại root repository:

```powershell
npm install
npm run dev
```

`predev` tự bật MariaDB, Redis, cập nhật firewall theo subnet LAN hiện tại và đợi API/DB/Redis sẵn sàng trước khi bật ba giao diện.

Pi:

```sh
cd ~/BravoForestRVM-Hieu
git checkout semi-final
git pull origin semi-final
sh deploy/pi/install-controller.sh
sh deploy/pi/start.sh
sh deploy/pi/launch-display.sh
```

Dừng Pi:

```sh
sh deploy/pi/stop.sh
systemctl --user stop bravoforest-camera-ai.service
```

## 7. Phần cứng và model

- Model PyTorch: `deploy/pi/models/best.pt`.
- Model tối ưu Pi mới nhất: `deploy/pi/models/best_ncnn_model/`.
- Controller: `deploy/pi/controller/main.py`.
- Firmware sản xuất: `deploy/pi/arduino/bravoforest_rvm/bravoforest_rvm.ino`.
- Sketch legacy đang dùng để thử: `deploy/pi/arduino-sorter/reference/arduino_sorter_test.ino`.
- Pi trước lần bàn giao gần nhất dùng CSI Picamera2, model NCNN, Arduino `/dev/ttyACM0`, protocol `legacy`.

Firmware legacy đã được sửa debounce cảm biến và điều khiển servo không chặn, nhưng chưa nạp lại bo vì Pi chưa có `arduino-cli` và chưa xác nhận FQBN của bo. Không chạy file `.pyc` tham khảo cùng controller vì sẽ tranh camera và Serial.

## 8. Thay đổi chính trong lần bàn giao

- Sửa mapping `clean_pet` không còn bị cảm biến kim loại đổi thành CAN.
- Ưu tiên class vật chứa đầy đủ thay vì `bottle_cap` nằm trong khung chai.
- Thêm hysteresis AI và debounce cảm biến.
- Thêm trạng thái AI thời gian thực vào `/health` camera và mục Hoạt động gần đây.
- Tách `Không hợp lệ` do AI khỏi `Lỗi thiết bị` do cảm biến/cơ cấu.
- Kiosk kiểm tra cấu hình machine ID/API key, timeout request và thông báo tiếng Việt.
- API CORS hỗ trợ LAN trong development; customer tự dùng hostname hiện tại khi mở từ thiết bị khác.
- `npm run dev` chờ API, MariaDB và Redis trước khi bật web, giảm lỗi `Failed to fetch` lúc khởi động.
- Admin dashboard và danh sách đã bỏ số liệu cứng, đọc database và giữ trạng thái rỗng cho biểu đồ/card.
- Cookie customer là session cookie để đóng trình duyệt sẽ kết thúc phiên đăng nhập.

## 10. Việc cần làm ngay trên Pi sau khi lấy code

1. Điền `deploy/pi/.env` từ file example, tuyệt đối không commit file này.
2. Xác nhận camera CSI và Arduino xuất hiện trong hệ điều hành.
3. Nạp firmware sau khi xác nhận đúng FQBN của bo Arduino.
4. Khởi động lại bằng các lệnh ở mục 6.
5. Thử một chai PET sạch: kiosk phải hiện ngay `PET sạch — đang xử lý`; sau cảm biến/servo hoàn tất mới xuất hiện `Hợp lệ` và cộng điểm.

Tại thời điểm tạo tài liệu này, Pi không còn phản hồi SSH ở IP LAN cũ nên bản trạng thái thời gian thực mới nhất đã được lưu trong Git nhưng chưa thể triển khai lại lên Pi.
